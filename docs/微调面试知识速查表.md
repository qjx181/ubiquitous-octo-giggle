# 微调面试知识速查表

> 适用于 NLP/RAG 方向面试，所有回答带"为什么"和"举一反三"

---

## 一、基础概念（必背4题）

### Q1 🔴 什么是微调（Fine-tuning）？和预训练有什么区别？

**回答：**
> 预训练是在海量通用数据（如整个互联网的文本）上训练模型从零学习语言能力，成本极高（数千张显卡 × 数月）。微调是在预训练好的模型基础上，用**少量领域数据**做继续训练，让模型适应特定任务。

**类比：**
- 预训练 = 一个人从小到大学完小学到大学的全部课程
- 微调 = 一个大学毕业生入职后，花一周时间学习公司内部的专业术语和规范

**面试官可能追问：** 微调会改变模型原有的能力吗？
> 会。微调是双刃剑——学新知识的同时可能遗忘旧知识（灾难性遗忘，Catastrophic Forgetting）。所以微调要用 LoRA 这类参数高效方法，尽量保留原有能力。

---

### Q2 🔴 LoRA 是什么？为什么有用？

**回答：**
> LoRA（Low-Rank Adaptation）的核心思想是：冻结原始模型的所有参数不动，在旁边加一小块可训练的参数矩阵。训练时只更新这个"小旁路"，推理时把旁路的结果加回原始输出。
>
> 为什么有用？一个 7B 模型的全部参数是 7B 个。LoRA 只训练约 0.1% 的参数（千万级别），显存占用从 30GB+ 降到 8-10GB。而且 LoRA 权重可以随时插拔——微调金融模型后，拔掉 LoRA 立刻恢复通用能力，不留下任何影响。

**参数含义：**
- `rank`（秩）——控制旁路矩阵的大小，rank=8 约 0.1% 参数，rank=64 约 1%
- `alpha`（缩放系数）——控制旁路的影响力，通常是 rank 的 2 倍（alpha=16 配合 rank=8）
- `target_modules`（目标模块）——对哪些层加旁路，一般选所有线性层（q/k/v/o/gate/up/down）

**举一反三：** 适配器模式（Adapter）也是类似思想——不修改原系统，加一个适配层。LoRA 是模型层面的"适配器模式"。

---

### Q3 ⚡ QLoRA 和 LoRA 有什么区别？

**回答：**
> QLoRA = LoRA + 4-bit 量化。LoRA 虽然只训练少量参数，但前向传播时原始模型的权重仍以 fp16（16位浮点数）加载，7B 模型仍需约 14GB 显存。QLoRA 把原始模型量化到 4bit，显存降到约 5GB，再加 LoRA 旁路约 1-2GB，**8GB 显存也能跑 7B 模型**。

| 方法 | 7B模型显存 | 训练速度 | 精度损失 |
|:---|:---:|:---:|:---:|
| 全量微调 | 30GB+ | 1x | 无 |
| LoRA (fp16) | 14GB | 1.2x | 极小 |
| QLoRA (4bit) | 6GB | 2x | 略低但可接受 |

**面试官可能追问：** 量化有精度损失，为什么 QLoRA 效果还行？
> 因为 LoRA 的参数仍然是 fp16 训练的，没有量化。量化的只是原始模型权重——原始模型的权重在推理时本身就会有一点精度冗余，4bit 损失的精度微乎其微。而且训练使用的梯度也存储在 LoRA 旁路里，不受量化影响。

---

### Q4 🔴 RAG 和微调有什么区别？为什么你选 RAG？

**回答：**
> RAG（检索增强生成）和微调是解决大模型领域知识不足的两种思路。
>
> **RAG：** 不修改模型，把外部知识检索出来当上下文塞进 prompt。知识可热更新——换一个 PDF 就换了一批知识。成本低，可溯源。
>
> **微调：** 修改模型参数，把知识"记住"。知识一旦记住就冻结了——想更新要重新训练，成本高。而且微调后的模型你不知道它从哪学来的知识，无法溯源。
>
> **选型理由：** 金融招股说明书场景，知识频繁更新（每家公司每季度出新的报告），且合规性要求回答必须可溯源。RAG 天然适合：检索到哪段原文就引用哪段，面试官问"你怎么保证回答有依据"时可以直接回答"每个回答都有 sources 引用来源"。

**面试官可能追问：** 那有没有 RAG + 微调结合的场景？
> 有。RAG 负责事实知识（需要更新和溯源的），微调负责风格和格式（不需要频繁更新的）。比如微调模型让他学会"用表格输出财务数据"的格式偏好，RAG 提供具体的数字。两者互补不冲突。

## 二、实战问题（必背3题）

### Q5 🔴 你的项目怎么微调？数据集怎么来的？

**回答（结合你的项目）：**
> 目标是微调 Qwen2.5-1.5B-Instruct 模型，让它在招股说明书问答场景回答更准确。数据集从系统的历史问答记录导出，格式为 Alpaca 格式（instruction + input + output）。使用 QLoRA 方法，rank=8，在 RTX 4060 8GB 上大约 1-2 小时训练。
>
> 工具选了 LlamaFactory，因为它有 WebUI 界面，可以可视化调整参数、实时看 loss 曲线、训练完直接测试效果。不用 Unsloth 是因为它需要 WSL 环境，而 WSL 的 CUDA 桥接在反向传播时会报错，LlamaFactory 的 Windows 原生支持更稳定。

**数据集样例：**
```json
{
  "instruction": "你是招股说明书分析助手。基于以下信息回答问题。",
  "input": "公司2023年的营业收入是多少？",
  "output": "根据招股说明书第三节'财务数据'，2023年营业收入为1,234.56亿元，同比增长15.3%。"
}
```

### Q6 🔴 怎么判断微调效果好还是不好？

**回答：**
> 从两个维度评估：
>
> ① **指标维度**——训练时看 loss 曲线，正常应该稳步下降。验证集 loss 如果先降后升说明过拟合了。用 BLEU、ROUGE 等指标评估生成质量。
>
> ② **人工维度**——找一些没见过的招股说明书问题，对比微调前后的回答质量。重点看：事实准确性（有没有造数据）、格式规范性（是否按要求的模板输出）、对专业术语的理解（ROE、DCF 等）。
>
> 关键区别：微调后模型可能在熟悉的数据上表现很好，但在不熟悉的公司上表现差——说明它"背"了数据而不是"理解"了模式。这是面试时区分"真做了"和"背了论文"的点。

---

### Q7 ⚡ 微调常见的坑有哪些？

**回答：**
>
> ① **过拟合**——数据量小（<500条）还训多个 epoch，loss 降到 0.0x 但生成质量反而差了。对策：用验证集监控，val loss 开始上升就早停。
>
> ② **灾难性遗忘**——模型学会了金融问答但忘记了通用对话能力。对策：混合 10-20% 的通用数据一起训练。
>
> ③ **数据质量 > 数据数量**——100 条高质量人工标注数据 > 10000 条从互联网爬的噪声数据。这是业界共识。
>
> ④ **WSL CUDA 问题**——在 WSL 里跑微调，backward pass 可能报 "CUDA driver error: device not ready"（我亲测过）。建议在 Windows 原生环境跑。

## 三、高频追问（3题）

### Q8 ⚡ 全量微调、LoRA、Adapter、Prefix Tuning 的区别？

| 方法 | 修改的参数 | 适用场景 | 面试价值 |
|:---|:---|:---|:---:|
| 全量微调 | 全部参数 | 大公司/大量数据 | 了解即可 |
| LoRA | 旁路矩阵（0.1%） | 个人开发者/小数据 | **必讲** |
| Adapter | 每层插小网络 | 多任务场景 | 了解即可 |
| Prefix Tuning | 输入前加虚拟 token | 生成任务 | 了解即可 |

面试时说 LoRA 就够了，其他几个提名字即可展示广度。

---

### Q9 🔵 微调时 batch size 设多少？为什么不是越大越好？

**回答：**
> 8GB 显存下，Qwen2.5-1.5B 用 QLoRA，batch_size=2 配合 gradient_accumulation=4（等效 batch=8）。不是越大越好，因为：
>
> ① 显存限制——batch 太大直接 OOM
> ② 小 batch 反而有正则化效果——噪声帮助模型逃离局部最优
> ③ 一般经验：等效 batch size（batch × accumulation）在 8-32 之间，对 1000 条数据足够

---

### Q10 🔵 你的 LLM 路由（SGLang/Ollama）微调后怎么部署？

**回答：**
> 微调产出的是 LoRA 权重文件（约 10-20MB），不是完整模型。部署时有两种方式：
>
> ① **合并后部署**——把 LoRA 权重合并回原始模型，导出完整模型文件（~3GB），替换 SGLang 上的模型路径
> ② **动态加载**——维持原始模型不变，推理时加载 LoRA 权重叠加
>
> 对学生项目，建议方案①——简单直接。如果面试官追问"合入和动态加载的区别"，回答：合入后用不了原模型了（通用能力丢失），动态加载可以随时插拔。我选合入是因为这个模型只做金融问答。
